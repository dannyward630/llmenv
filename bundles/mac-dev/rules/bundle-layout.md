# macOS Bundle Layout

## App bundle anatomy

    MyApp.app/Contents/
      Info.plist            # required; only Info.plist + PkgInfo at this level
      MacOS/MyApp           # main executable (+ CLI helper executables)
      Resources/            # assets, nibs, *.lproj — sealed as DATA
      Frameworks/           # embedded .framework bundles and .dylibs
      PlugIns/              # loadable .bundle / app-extension .appex
      XPCServices/          # .xpc service bundles
      Library/LoginItems/   # SMLoginItemSetEnabled helper apps
      Helpers/              # privileged/auxiliary executables
      _CodeSignature/       # generated by codesign; never hand-edit

Placement is load-bearing for code signing:

- **MUST NOT put stray files in `Contents/` root** — anything besides `Info.plist`,
  `PkgInfo`, and the known subdirectories yields "unsealed contents" /
  invalid-signature errors.
- **Executables and dylibs MUST NOT go in `Resources/`** — resources are
  sealed as data, so nested code there breaks signing and notarization.
- **Code MUST go in** `MacOS/`, `Frameworks/`, `PlugIns/`, `XPCServices/`,
  `Helpers/` — signed per-item, inside-out.
- MUST NOT add/remove/edit files inside an already-signed bundle without
  re-signing it.

## Framework bundle anatomy (macOS = versioned)

    Foo.framework/
      Foo        -> Versions/Current/Foo
      Headers    -> Versions/Current/Headers
      Resources  -> Versions/Current/Resources
      Versions/
        A/
          Foo                    # the dylib binary
          Headers/
          Resources/Info.plist   # NOTE: no top-level Info.plist on macOS
          _CodeSignature/
        Current -> A

- macOS frameworks MUST be **versioned**; iOS-style shallow frameworks
  (binary + Info.plist at top level) are invalid on macOS and vice versa.
- The top-level entries are **symlinks**. MUST copy frameworks with
  `ditto` or `cp -a` (symlink-preserving); a symlink-flattening copy
  (or a zip made without `ditto -c -k`) produces a framework that
  fails `codesign --verify`.
- MUST sign the versioned directory (`codesign ... Foo.framework/Versions/A`),
  not the top-level symlink.

## Resources and localization

- MUST look up resources with the APIs, and MUST NOT use paths built off `argv[0]`:
  `Bundle.main.url(forResource:withExtension:)`,
  `Bundle(for: SomeClass.self)`, `[NSBundle bundleForClass:]`,
  `Bundle.module` (SwiftPM resources), `CFBundleCopyResourceURL`.
- Localized resources: `Resources/<lang>.lproj/` (`en.lproj`,
  `Base.lproj`, …) holding `Localizable.strings`, nibs, etc.
  `CFBundleDevelopmentRegion` names the fallback.

## Info.plist required keys

Every key in this table is REQUIRED.

| Key | Note |
|-----|------|
| `CFBundleIdentifier` | reverse-DNS, unique — signing/notarization key |
| `CFBundleExecutable` | MUST match the binary name in `MacOS/` |
| `CFBundlePackageType` | `APPL` app, `FMWK` framework, `BNDL` bundle |
| `CFBundleName` / `CFBundleDisplayName` | short name / UI name |
| `CFBundleShortVersionString` | user-facing version (1.2.3) |
| `CFBundleVersion` | build number, monotonically increasing |
| `LSMinimumSystemVersion` | Gatekeeper checks it against min-OS |
| `NSPrincipalClass` | `NSApplication` for app bundles |
